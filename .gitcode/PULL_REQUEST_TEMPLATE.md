## 【合入来源】

> 勾选适用分类，可多选；有关联的公开 issue、PR 或设计资料时附链接。请勿附内部流程信息或敏感数据。

- [ ] 需求
- [ ] 问题单
- [ ] issue/工单
- [ ] 重构优化
- [ ] 资料更新

## 【修改说明】

> 说明为什么修改、主要实现方式及改后行为。涉及适配或架构时，按 ARCHITECTURE.md 的设计原则简述：使用的上游扩展接口、行为或状态影响、相关验证（填入下方“验证结果”）。无关项无需展开。

## 【资料变更】

> 说明是否涉及文档或使用说明变更；如有，列出相关文档及修改内容，不涉及时注明“不涉及”。

## 【兼容性影响】

> 说明现有接口、配置或依赖是否变化；如有，说明影响及必要的迁移方式，无影响时注明“无”。

## 【验证结果】

> 说明测试场景、验证方式、实际结果，以及新增或复用的回归用例。命令、环境、日志或报告按复现需要提供；未执行项说明原因，需要协助时说明所缺条件。文档修改说明相应检查结果即可。
>
> 涉及数值或性能声明时，附比较对象、测试条件与结果，说明适用范围及收益与代价。

## 【CheckList】

> 已完成的项目勾选；未完成的保留未勾选并说明原因。不适用项注明“不适用”及原因，不计为验证通过。检查证据统一写在上方“验证结果”中。

- [ ] PR 标题使用适当的类型前缀，如 feat、fix、refactor、docs、test。
- [ ] 必要的代码注释、错误处理和日志已核对。
- [ ] 受影响的接口、配置、依赖及相关文档已同步。
- [ ] 相关回归测试已新增或复用，并记录执行结果。
- [ ] 适用的静态检查和 CI 检查已通过。
